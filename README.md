# Bybit — коннектор для Claude

Локальный MCP-сервер для [Bybit API V5](https://bybit-exchange.github.io/docs/v5/intro), упакованный как расширение Claude Desktop (`.mcpb`). Все настройки задаются в интерфейсе Claude: при установке и потом, у уже установленного коннектора.

## Что умеет

| Что подключено | Что доступно |
|---|---|
| Ничего | Открытые методы API: цены, свечи, стакан, последние сделки, ставки финансирования, открытый интерес, параметры инструментов, объявления, статус системы, публичные WebSocket-потоки |
| Демо-счёт (`api-demo.bybit.com`) | Плюс баланс, позиции, ордера, история. Торговля и операции со средствами, включая пополнение демо-счёта |
| Реальный счёт (`api.bybit.com`) | Плюс данные счёта. Торговля и операции со средствами — только после включения переключателей в настройках |
| Оба счёта | Всё перечисленное. Счёт выбирается в каждом запросе, для чтения есть счёт по умолчанию |

Кроме того:

- **Все REST-методы V5.** Каталог из 466 методов собран из официальной документации. Любой метод можно найти, посмотреть его параметры и вызвать.
- **Подпись запросов.** Поддерживаются системные ключи (HMAC-SHA256) и собственные RSA-ключи. Часы сверяются с сервером Bybit. Если Bybit отклонил запрос из-за времени (`10002`), запрос повторяется.
- **WebSocket.** Коннектор подключается к потоку на несколько секунд и возвращает собранный стакан, итоговый тикер, сделки или события по ордерам и позициям.
- **Оповещения без опросов.** Агент задаёт условие (уровень цены, сдвиг на процент, закрытие свечи, статус ордера, изменение позиции) и ждёт его через `Monitor` в Claude Code. Коннектор сам следит за потоками Bybit и будит агента одним сообщением, когда условие выполнилось. Подробнее — в разделе [«Оповещения»](#оповещения).
- **Проверка параметров до отправки.** Имена, типы и обязательные поля сверяются с каталогом. Числа приводятся к строкам там, где Bybit ждёт строки (`qty`, `price`). В торговых запросах опечатка в имени параметра считается ошибкой.
- **Никаких зависимостей.** Нужен только Node.js 22+ (в Claude Desktop он встроен): так меньше чужого кода рядом с ключами от биржи.
- **Протокол MCP 2026-07-28** (без рукопожатия, с `server/discover`), а также прежние версии 2025-11-25 и старше.

## Установка

1. Соберите пакет (нужен Node.js 22+; упаковщик `@anthropic-ai/mcpb` загрузит `npx`):

   ```bash
   npm run pack
   ```

   Получится `dist/bybit-mcp.mcpb`.

2. Установите его в Claude Desktop любым способом:
   - откройте файл двойным щелчком;
   - перетащите его в окно Claude Desktop;
   - **Settings → Extensions → Advanced settings → Install Extension…** и выберите файл.

3. В окне установки заполните настройки (см. таблицу ниже). Все поля необязательные: если ничего не заполнять, будут доступны открытые методы API.

4. Проверьте подключение: попросите Claude «проверь подключение к Bybit». Он вызовет `connector_status` и покажет, какие счета подключены и что на них разрешено. С `check_keys: true` Bybit проверит сами ключи: права, привязку к IP, срок действия.

### Изменение настроек

Настройки уже установленного коннектора: **Settings → Extensions → Bybit**. Там те же поля, что и при установке. После сохранения Claude Desktop перезапускает коннектор, и набор инструментов меняется под новые настройки: например, после включения торговли появятся торговые инструменты. Если изменения не подхватились, выключите и снова включите расширение.

### Обновление без потери ключей

Новую версию ставьте поверх старой, не удаляя расширение:

1. Соберите пакет: `npm run pack`.
2. Откройте `dist/bybit-mcp.mcpb` двойным щелчком (или **Settings → Extensions → Advanced settings → Install Extension…**) и подтвердите установку.

Claude Desktop узнаёт то же расширение по имени и автору из `manifest.json` и переносит введённые настройки, включая зашифрованные ключи API. Удалять расширение перед установкой не нужно: удаление стирает его настройки вместе с ключами, и вводить их придётся заново.

Разрешения на отдельные инструменты («Always allow») привязаны к названию коннектора и именам инструментов. Если они изменились, как в 1.1.0 и 1.1.1, такие разрешения выдаются заново.

Со стороны разработки перенос ключей охраняет тест: ключи полей `user_config` и пометки `sensitive` менять нельзя. Claude Desktop переносит значение, только если поле с тем же ключом есть в новой версии, а зашифрованное значение — только если поле осталось `sensitive`.

### Настройки

| Поле | Зачем |
|---|---|
| Реальный счёт: API Key / API Secret | Ключ основного счёта. Без него реальный счёт используется только для открытых данных |
| Реальный счёт: разрешить торговлю | Ордера, позиции, плечо, TP/SL, режим маржи. По умолчанию выключено |
| Реальный счёт: разрешить операции со средствами | Переводы, вывод, конвертация, займы, Earn, субаккаунты, API-ключи. По умолчанию выключено. Не зависит от переключателя торговли |
| Демо-счёт: API Key / API Secret | Ключ демо-счёта. На демо-счёте разрешены все операции |
| Счёт по умолчанию | `auto`, `mainnet` или `demo`: куда идут запросы чтения без явного указания счёта. `auto` выбирает демо-счёт, если задан его ключ, иначе реальный. Понимает и `реальный`, `демо`, `авто` |
| Реальный счёт: адрес API | Только для региональных аккаунтов: `https://api.bybit.eu`, `https://api.bybit.nl`, `https://api.bybit.tr`, `https://api.bybit.kz`, `https://api.bybit.id`, `https://api.bybitgeorgia.ge`, `https://api.bybit.ae`, `https://api.bytick.com`, `https://api.manepa.jp`, `https://api.spark-fintech.com` |
| recv_window, мс | Сколько подписанный запрос остаётся действительным, по умолчанию 5000 |
| Брокерский Referer | Только для брокеров Bybit |

Ключи хранятся в защищённом хранилище системы: Claude Desktop шифрует поля, помеченные как секретные.

### Как получить ключи

- **Реальный счёт:** bybit.com → профиль → API → создать ключ. Если торговать через Claude не нужно, выберите права «только чтение».
- **Демо-счёт:** на bybit.com переключитесь в режим Demo Trading и создайте ключ в разделе API. У демо-счёта свой UID и свои ключи. Ключи реального счёта на демо не работают, и наоборот: Bybit ответит `10003`.

Привязывайте ключи к IP-адресу. По документации Bybit ключи без привязки к IP перестают действовать через 90 дней.

## Безопасность

Методы разделены на три уровня доступа, у каждого свой инструмент:

| Уровень | Инструмент | Что входит | Реальный счёт | Демо-счёт |
|---|---|---|---|---|
| чтение | `send_read_request` | рынок, балансы, позиции, ордера, история, записи о вводе и выводе | всегда | всегда |
| торговля | `send_trading_request` | ордера, позиции, плечо, TP/SL, режим маржи, спреды, RFQ, боты | переключатель «разрешить торговлю» | всегда |
| средства | `send_funds_request` | переводы, вывод, конвертация, займы, Earn, субаккаунты, API-ключи | переключатель «разрешить операции со средствами» | всегда |

- По умолчанию на реальном счёте разрешено только чтение.
- Claude видит только те инструменты, которые можно выполнить при текущих настройках. Без ключей нет инструментов счёта, при выключенной торговле нет торговых. Скрытые возможности сервер перечисляет в инструкциях для модели вместе с полем настроек, которое их включает.
- Инструменты чтения помечены как безопасные. В Claude Desktop их можно разрешить навсегда, а торговлю и операции со средствами подтверждать каждый раз.
- Для торговли и операций со средствами счёт (`env`) нужно указывать явно, поэтому запрос не уйдёт на реальный счёт случайно.
- Если счёт не указан, а по умолчанию выбран демо-счёт, открытые методы вне списка демо-сервиса (объявления, статус системы и т. п.) запрашиваются с адреса реального счёта без подписи: данные одинаковы, а ключ не используется.
- Некоторым методам на реальном счёте нужны оба переключателя:
  - созданию торговых ботов: бот забирает средства на свой счёт и торгует сам;
  - любому POST-методу, которого нет в каталоге. Такой метод вызывается только через `send_funds_request`. GET вне каталога идёт через чтение.
- `watch_stream` отказывается подписываться на темы `dcp`: после закрытия такого соединения Bybit может отменить все активные ордера.
- Изменяющий запрос не отправляется повторно после сетевого сбоя. На таймаут или ошибку сервера Bybit ответ содержит поле `outcome`: исход неизвестен, сначала нужно проверить состояние счёта.
- Если у нового ордера нет `orderLinkId`, коннектор задаёт его сам и сообщает в ответе: по нему ордер можно найти.
- У пакетных ордеров видны частичные ошибки (`itemErrors`). У ботов виден отказ, даже если `retCode` равен 0.
- Запросы уходят только на адрес выбранного счёта: хост из переданного URL игнорируется, перенаправления запрещены. Адрес реального счёта принимается только из списка доменов Bybit, адрес демо-счёта — только `api-demo.bybit.com` (для локальных тестов в обоих случаях допускается `localhost`).
- Если ключ задан, но секретом нельзя подписать запрос (например, повреждён RSA-ключ), счёт не считается подключённым, а `connector_status` показывает причину.
- Подсказки коннектора называют и поле настроек Claude Desktop, и переменную окружения — для ручного подключения.
- Ключи не попадают ни в ответы, ни в описания инструментов: `connector_status` показывает только первые символы. Значения неверно заполненных полей тоже не попадают в сообщения об ошибках.

Главная защита — права самого ключа. Если торговать не собираетесь, создайте ключ «только чтение».

## Оповещения

Агенту не нужно раз в несколько минут спрашивать цену или статус ордера и тратить на это токены. Он создаёт оповещение, а коннектор сам держит соединение с Bybit и будит агента, только когда условие выполнилось.

1. Агент вызывает `create_alert`. Коннектор подписывается на нужные потоки Bybit, проверяет символ и поле, запоминает текущее значение и возвращает объект `monitor` с локальным адресом `ws://127.0.0.1:<порт>/alerts/<токен>`.
2. Агент запускает с этим объектом инструмент `Monitor` Claude Code. Пока условие не выполнено, по соединению ничего не приходит.
3. Условие выполнилось — в соединение уходит одно JSON-сообщение: что сработало, значение, время и заметка агента (`note`). Monitor превращает его в уведомление и будит агента.
4. Оповещение с `frequency: once` на этом заканчивается: коннектор закрывает соединение кодом 4000, и Monitor останавливается.

Пример события:

```json
{"alert":"6e030abd","note":"вход по пробою","events":[{"seq":1,"at":"2026-09-21T16:25:00.000Z","condition":1,"summary":"ETHUSDT spot 1m candle 16:24-16:25 UTC closed: close 2758.39 >= 1","value":"2758.39","data":{"open":"2759.65","close":"2758.39","…":"…"}}],"status":"finished"}
```

| Тип условия | Что проверяется | Пример |
|---|---|---|
| `ticker` | поле тикера (`lastPrice` по умолчанию, `markPrice`, `indexPrice`, `bid1Price`, `fundingRate`, `openInterest` и др.) выше или ниже уровня (`above`, `below`) либо сдвиг на процент от текущего значения (`rise_pct`, `fall_pct`, `move_pct`) | BTCUSDT на фьючерсах дошёл до 70 000 |
| `candle` | закрытая свеча: `close`, `open`, `high`, `low`, `volume`, `turnover`, `change_pct`, `range_pct` выше или ниже значения | 15-минутная свеча ETHUSDT закрылась ниже 3000 |
| `order` | ордер (по `order_id` или `order_link_id` либо любой ордер категории и символа) перешёл в один из статусов; по умолчанию — завершающие: `Filled`, `PartiallyFilledCanceled`, `Cancelled`, `Rejected`, `Deactivated` | лимитный ордер исполнился |
| `position` | позиция символа открылась, закрылась, изменила размер или ушла в ликвидацию; разворот одной сделкой (Buy → Sell) считается закрытием и открытием | сработал TP или SL |

`order` и `position` появляются, когда подключён ключ счёта. События приходят из приватного потока Bybit; на счёте коннектор при этом ничего не меняет.

В одном оповещении — до 10 условий, срабатывает любое. Частота (`frequency`):

- `once` (по умолчанию) — оповещение заканчивается первым событием;
- `once_per_condition` — каждое условие срабатывает один раз, оповещение заканчивается, когда сработали все;
- `every_time` — условие срабатывает снова, когда перестало выполняться и выполнилось опять, но не чаще `cooldown_seconds` (по умолчанию 60 с). Для свечей, ордеров и позиций — каждое подходящее событие.

Оповещение живёт 24 часа, если не задан `expires_in_minutes` (до 7 суток). `list_alerts` показывает текущие значения, сработавшие и недоставленные события, подключён ли Monitor, и тот же объект `monitor` для переподключения. `cancel_alert` отменяет одно оповещение или все.

### Надёжность

- Monitor живёт не дольше 30 минут. Агент запускает его снова по тому же адресу, и всё, что сработало в перерыве, приходит сразу.
- Доставка подтверждается. После каждого сообщения коннектор шлёт ping, и pong от Monitor означает, что сообщение прочитано. Если соединение оборвалось раньше, сообщение уйдёт повторно с пометкой `redelivered`.
- Условие, которое уже выполнено при создании (цена уже выше уровня), срабатывает сразу, а ответ `create_alert` помечает его `already_met`.
- Ордер по id сначала проверяется по REST: если он исполнился ещё до подписки, событие не теряется. Позиция берёт отправную точку по REST, а устаревшие обновления отбрасываются по `seq`. Повторные сообщения о том же статусе ордера не дублируют событие.
- Поток Bybit оборвался — коннектор переподключается и подписывается заново. Если связи нет дольше минуты, агент получает об этом событие, а после восстановления — ещё одно. Пропущенные закрытия свечей добираются по REST, ордера по id и позиции сверяются заново.
- Коды закрытия 4000–4005 значат, что этот Monitor больше не нужен и перезапускать его не надо: оповещение закончилось или его слушает другой Monitor. Если же Monitor не смог подключиться (`1006 Failed to connect`), коннектор перезапускался: `list_alerts` покажет, что оповещения нет, и его нужно создать заново.

  | Код | Причина |
  |---|---|
  | 4000 | условия сработали, все события доставлены |
  | 4001 | к оповещению подключился другой Monitor |
  | 4002 | оповещение отменено |
  | 4003 | истёк срок |
  | 4004 | адрес неизвестен: коннектор перезапускался или адрес неверен |
  | 4005 | коннектор остановлен |

### Безопасность и ограничения

- Сервер оповещений слушает только `127.0.0.1`, порт выбирает система. В адресе — случайный токен на 144 бита.
- Подключения из браузера (с заголовком `Origin`) и с чужим `Host` отклоняются, поэтому веб-страница не сможет подслушать события счёта.
- Оповещения живут в памяти коннектора. После его перезапуска (смена настроек, обновление, перезапуск Claude) их нет: Monitor не подключится или получит код 4004, и агент создаст оповещение заново.
- Monitor есть в Claude Code. В обычном чате Claude Desktop разбудить агента некому, но состояние оповещения видно через `list_alerts`.
- Тикеры Bybit присылает раз в 50–100 мс, и очень короткий всплеск цены между обновлениями может остаться незамеченным.

## Ограничения

- WebSocket-API для выставления ордеров (`/v5/trade`) не поддерживается: всё то же самое делается через REST. На демо-счёте Bybit его и не предоставляет.
- Не поддерживаются протоколы для маркет-мейкеров и институциональных клиентов: бинарный SBE и выделенные шлюзы MMGW/MMWS.
- На демо-счёте работает только часть методов (см. `demo_only` в поиске). Остальные сервер Bybit отклонит, и коннектор это пояснит.
- Bybit не обслуживает часть регионов (например, IP-адреса из США) и временно блокирует IP при слишком частых запросах. В обоих случаях приходит HTTP 403.
- Testnet (`api-testnet.bybit.com`) не настроен.

## Подключение без пакета

Сервер можно прописать вручную. Учтите, что в этом случае ключи лежат в файле конфигурации открытым текстом.

Claude Desktop, файл `claude_desktop_config.json` (**Settings → Developer → Edit Config**):

```json
{
  "mcpServers": {
    "bybit": {
      "command": "node",
      "args": ["/путь/к/bybit-mcp/server/index.js"],
      "env": {
        "BYBIT_DEMO_API_KEY": "…",
        "BYBIT_DEMO_API_SECRET": "…"
      }
    }
  }
}
```

Claude Code:

```bash
claude mcp add bybit -e BYBIT_DEMO_API_KEY=… -e BYBIT_DEMO_API_SECRET=… -- node /путь/к/bybit-mcp/server/index.js
```

Все переменные окружения:

| Переменная | По умолчанию | |
|---|---|---|
| `BYBIT_MAINNET_API_KEY`, `BYBIT_MAINNET_API_SECRET` | — | ключ реального счёта |
| `BYBIT_MAINNET_API_SECRET_FILE` | — | секрет или PEM из файла |
| `BYBIT_MAINNET_ALLOW_TRADING` | `false` | торговля на реальном счёте |
| `BYBIT_MAINNET_ALLOW_FUNDS` | `false` | операции со средствами на реальном счёте |
| `BYBIT_MAINNET_BASE_URL` | `https://api.bybit.com` | региональный адрес: только домены Bybit |
| `BYBIT_MAINNET_STREAM_URL` | выводится из REST-адреса | адрес WebSocket |
| `BYBIT_DEMO_API_KEY`, `BYBIT_DEMO_API_SECRET`, `BYBIT_DEMO_API_SECRET_FILE` | — | ключ демо-счёта |
| `BYBIT_DEMO_BASE_URL`, `BYBIT_DEMO_STREAM_URL` | `https://api-demo.bybit.com`, `wss://stream-demo.bybit.com` | только для тестов: другой адрес, кроме `localhost`, не принимается |
| `BYBIT_DEFAULT_ENV` | `auto` | `auto`, `mainnet`, `demo` |
| `BYBIT_RECV_WINDOW` | `5000` | мс, 1000–60000 |
| `BYBIT_TIMEOUT_MS` | `15000` | таймаут HTTP-запроса |
| `BYBIT_MAX_OUTPUT_CHARS` | `60000` | предел длины ответа; длинные списки укорачиваются с пометкой |
| `BYBIT_REFERER` | — | заголовок `X-Referer` для брокеров |

## Обновление каталога методов

Каталог (`server/catalog.json`) собирается из [исходников документации](https://github.com/bybit-exchange/docs). Из них берутся только факты: пути, параметры, типы, перечисления. Тексты описаний `describe_endpoint` подтягивает при запросе.

```bash
git clone --depth 1 --filter=blob:none --sparse https://github.com/bybit-exchange/docs.git /tmp/bybit-docs
git -C /tmp/bybit-docs sparse-checkout set docs/v5
npm run catalog -- /tmp/bybit-docs
npm test
```

Скрипт выводит сводку:

- сколько методов на каждом уровне доступа;
- предупреждения разбора;
- методы, открытые без авторизации;
- POST-методы уровня «чтение» (`readPosts`). Этот список стоит просматривать при каждой пересборке: такие методы можно разрешить в Claude Desktop навсегда.

Новые POST-методы по умолчанию попадают на уровень «средства». Если метод на самом деле торговый, добавьте его в `TRADE_PATHS` в `scripts/build-catalog.mjs`.

## Разработка

```bash
npm test                                   # тесты, без обращений к сети
npm run call                               # список инструментов
npm run call -- get_tickers '{"category":"linear","symbol":"BTCUSDT"}'
npm run validate                           # проверка manifest.json
npm run pack                               # dist/bybit-mcp.mcpb
```

`scripts/call.mjs` берёт настройки из тех же переменных окружения, что и сервер. Журнал сервера пишется в stderr. Claude Desktop сохраняет журналы в `~/Library/Logs/Claude/` (`mcp.log` и `mcp-server-*.log`).

Оповещение можно попробовать и без Claude Desktop: `npm run call -- create_alert '{"conditions":[{"type":"ticker","category":"linear","symbol":"BTCUSDT","op":"move_pct","value":0.05}]}'` печатает объект `monitor` и продолжает работать, пока процесс не остановят. К адресу из ответа можно подключить `Monitor` в Claude Code или любой клиент WebSocket.

```

test/                тесты (node:test)
```
